# Human Organoid Donor-Aware Split Decision

Status: draft decision checkpoint
Date: 2026-05-22
Task: `draft_human_organoid_spaceflight`

## Decision

Keep GEO-derived donor/Subject holdouts as diagnostic-only folds. Do not promote
them to the default benchmark split and do not create a separate leaderboard
task yet.

The manifest should continue to expose:

- default folds: organoid-type holdouts and microglia-condition holdouts;
- diagnostic folds: `donor_diagnostic_folds`;
- claim boundary: `donor_diagnostic_only_not_leaderboard`.

## Rationale

External split guidance supports group-aware evaluation when samples come from
subjects, experiments, or devices. scikit-learn's cross-validation guide notes
that when samples have a group structure, group-wise cross-validation is safer,
and that validation samples should come from groups not represented in the
paired training fold. `GroupKFold` similarly defines non-overlapping groups, and
`LeaveOneGroupOut` holds out one group at a time.

That rule is useful here, but only as a diagnostic. In GSE259421, donor/Subject
is not independently crossed with the other major design factors:

- Subject1 and Subject2 are OSD-863 cortical organoids.
- Subject3 and Subject4 are OSD-871 dopaminergic organoids.
- Disease context is coupled to organoid fate and source.
- All samples are from one ISS mission context.

Therefore donor holdout tests a mixture of donor, source, organoid fate, disease
context, and expression-scale effects. It is not a clean donor-generalization
benchmark.

## Implementation Boundary

Implemented:

- `HumanOrganoidTaskData.diagnostic_folds`
- `run_human_organoid_donor_diagnostics`
- `scripts/run_v9_human_organoid_donor_diagnostics.py`
- donor diagnostic report artifacts under
  `v9/human_organoid/reports/donor_diagnostics/`

Not implemented:

- no new leaderboard task id;
- no donor-generalization claim;
- no hyperparameter selection based on donor folds;
- no promotion of raw-count sensitivity variants based on donor diagnostics.

## Next Step

Keep donor diagnostics available for reviewers and methods sanity checks. The
next organoid block should either:

1. add DE/signature reference metrics for the current pilot; or
2. create a very small `human_organoid_donor_diagnostic` task only if release
   docs clearly state that it is a confounded diagnostic, not a clean
   donor-generalization benchmark.

Recommended direction: do not create the separate task yet. Add DE/signature
metrics first, because they are closer to the biological claims in the GEO
record and publication.
