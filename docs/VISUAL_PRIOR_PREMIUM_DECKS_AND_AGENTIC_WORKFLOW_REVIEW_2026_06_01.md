# Prior Premium Decks And Agentic Workflow Review

Date: 2026-06-01

Purpose: review JK's prior premium slide-deck work and local agent/skill
systems before continuing the SpaceBio-Bench deck. This is a calibration memo,
not a template-copy instruction. The goal is to identify which visual,
narrative, and QA habits should govern the next B1-B4 rebuild and later
presentation/manuscript production.

## Bottom Line

The strongest prior decks did not become premium by adding more decoration.
They became premium when they locked a claim spine, placed one dominant proof
object on each slide, layered interpretation above evidence, and ran visual QA
against rendered slides/contact sheets.

For SpaceBio-Bench, the correct transfer is:

> layered proof-object scenes + editable scientific interpretation + explicit
> evidence-tier and release-boundary control

The prior decks confirm the current visual-identity decision:

> Mission-grade scientific benchmark system

But they also sharpen it: the next build should behave like a scientific
benchmark control room with journal-level evidence restraint, not like a
dashboard, a workflow diagram pack, or a generic space-themed keynote.

## Updated SpaceBio-Bench Slide Rules

### 1. Reference Decks Are Calibration Anchors, Not Templates

Use ISGP for live rhythm, KMU for proof-stage transformation, AWG for
sponsor-grade share safety, K562 for compact scientific proof-object clarity,
PBS for abstract benchmark concept explanation, and Trivedi for late ecosystem
placement. Do not merge all styles into one slide.

### 2. Each Mainline Slide Needs A Role

Every slide must declare one of:

- `live_thesis`
- `method_bridge`
- `proof_object`
- `result_interpretation`
- `release_boundary`
- `appendix_table`
- `ecosystem_or_future_work`

Tables and internal decision records are not figures. They should become
appendix/table artifacts unless the slide's role is explicitly `appendix_table`.

### 3. Visible Text Must Be Plain Before Technical

The first read should be intuitive. Use technical labels as smaller second
labels when needed.

Preferred pattern:

- headline: plain scientific claim;
- callout: what the viewer should notice;
- small label: exact term, dataset, model, tissue, species, or metric.

Avoid:

- visible internal labels such as `loose matrix`, `candidate`, `decision`,
  `micro-plan`, `wireframe`, `proof-of-quality prototype`;
- jargon-only headlines such as `RRRM externalization` or `LOMO/LOTO transfer`
  unless immediately translated on the slide face.

### 4. Z-Stack Must Carry Scientific Meaning

Use the existing Z0-Z7 layers as semantic layers:

| Layer | SpaceBio-Bench Use | Prior-Deck Calibration |
|---|---|---|
| Z0 canvas/atmosphere | mission-grade field, no wallpaper | ISGP, hybrid style frame |
| Z1 measurement layer | assay lanes, tissue/species ticks, mission boundary rail | ISGP/KMU |
| Z2 evidence surface | source-derived figure, manifest, result plate | AWG/K562/PBS |
| Z3 proof object | task document, UMAP/heatmap/result crop, dataset stack | K562/AWG |
| Z4 interpretation | editable headline/callout/focus label | all premium decks |
| Z5 trust boundary | train-only guard, held-out mission/species, release boundary | ISGP/PBS |
| Z6 caveat/status | source tier, preliminary/internal/public, manuscript-safe caveat | AWG/PBS |
| Z7 motion/focus | one transfer path or transformation line | ISGP/KMU |

Depth is a hierarchy tool. If every object casts the same shadow, the slide
fails the z-stack rule.

### 5. Method Slides Need Visual Comprehension, Not More Explanation

For first-time viewers, the method should be visible as an operating model:

`public space-biology studies -> frozen evidence/task surface -> train-only
context -> held-out transfer test -> benchmark score -> diagnostic follow-up`

Recommended B1-B4 rebuild jobs:

- B1: Public studies become an auditable benchmark surface.
- B2: Data collection and processing freeze source context before modeling.
- B3: The held-out mission/species/tissue/cell context is the trust boundary.
- B4: Scores become diagnosis only when task provenance and caveats travel
  with the result.

### 6. QA Must Be A Gate, Not A Memory

Before calling any slide premium:

- render a full-size PNG/PDF;
- inspect at full size;
- inspect a zoom crop of the proof object and source/status strip;
- add or update a contact sheet;
- scan visible text for internal language and jargon-only labels;
- verify the claim tier against source/manuscript notes;
- record the slide role, z-layers, source paths, and caveat in a manifest.

## Immediate Implementation Implications

1. Do not continue polishing old B2-B4 candidates as final slides. Treat them
   as logic wireframes.
2. Build B1 as the brand stress test using the selected hybrid visual identity.
3. Rebuild B2-B4 only after B1 passes contact-sheet and zoom review.
4. Keep Fig1/Fig2/Fig3/Fig6 manuscript variants flatter, but use the same
   proof-object hierarchy.
5. Add a visible-jargon audit to every rendered slide before PPTX assembly.
6. Keep internal guide and decision text out of slide faces; store it in
   manifests, QA reports, speaker notes, or appendix docs.

## Open Risks

- The current project already has many visually improved assets, but not all
  were designed from a locked brand system. They need reference-gate review
  before being promoted.
- A warm editorial canvas can drift beige if mission navy/source blue/bio green
  are not used as anchors.
- Dark mission-system slides can drift into sci-fi if not tied to actual
  evaluation boundaries.
- Tables inside figure panels will still look awkward for journal-style main
  figures; table content should become table artifacts.
- The final deck will need profile-specific QA: live-talk rhythm if presented,
  leave-behind share safety if sent, and manuscript figure discipline if
  converted into a paper.
